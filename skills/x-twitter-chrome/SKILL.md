# X/Twitter 已登录 Chrome 访问

## 固定边界

- 只使用运行时明确提供的 Chrome 控制工具，并复用用户已经登录的同一个 Chrome。
- 不使用内置网页浏览器、Jina、抓取代理、X API、Cookie 导出或其他登录方式代替。
- 不自动登录，不输入、读取或转存密码、验证码、Cookie、令牌。
- Chrome 不可控、没有已登录状态或页面状态无法确认时立即停止，说明阻塞。
- 最多允许在同一个 Chrome 中进行一次可逆的页面重新打开；失败后保留不确定性。

## 只读访问

查看帖子、个人资料、通知、搜索结果和公开互动属于只读操作，可以直接执行。只依据
当前可见页面作答；局部渲染、加载失败或状态不完整时，不把“未看到”表述为“不存在”。

## 外部副作用

以下动作一律视为外部副作用：点赞、取消点赞、回复、转发、引用、发布、删除、关注、
取消关注、私信，以及任何会改变账户或公开状态的点击。

执行前必须获得由运行时确认闸门签发的批准，且批准同时满足：

1. 绑定单一动作类型；
2. 绑定精确目标 URL 或账号；
3. 绑定精确正文；无正文的动作也要明确记录；
4. 包含一次性动作 ID 和有效期；
5. 尚未使用、未过期，且页面上的最终动作与批准内容完全一致。

如果当前运行时只提供普通聊天确认、没有可验证的一次性确认回执，不得执行。此时只
输出确认草案并停止：

```text
需要确认的 X 动作
动作：<精确动作>
目标：<精确 URL 或账号>
正文：<精确正文或“无”>
有效期：<运行时给出的期限>
```

批准过期、被拒绝、正文变化、目标变化、动作变化或动作 ID 复用时都必须拒绝。不得把
用户对任务的普通描述解释为批准。

## 执行与回执

取得有效批准后，只执行一次批准动作。执行后用可见页面状态核对结果；无法确认时报告
“已尝试但未确认”，不得重复点击。回复中不得泄露账号标识、认证状态、Cookie、令牌或
本机路径。
